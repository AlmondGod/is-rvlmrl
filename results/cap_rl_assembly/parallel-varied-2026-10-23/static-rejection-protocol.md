# Strict zero-reward execution filter

assigned zero before physical execution. A strict-only static filter also rejects
programs missing an API call that the frozen executor/evaluator necessarily
requires: four distinct positions, releases, corner and panel nails, plus park,
feed, sheet position/release, flip and finish. This proves only zero binary
reward. It does not check geometric feasibility or predict success; every
non-rejected complete program uses the actual physical evaluator. Dense reward
for a statically rejected program is recorded as unknown (`null`), not measured
zero. The proof is guarded by executor/evaluator/parser source hashes and is
recorded with each rejected program. No program is repaired or used as a target.


This optimizer-only amendment leaves the frozen physical source unchanged, so exact program/layout evidence from the initial baseline can be reused. It is introduced before optimizer updates and before held-out evaluation.
